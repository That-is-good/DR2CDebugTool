# Death Road to Canada Debug Tool

## Project Overview

A memory editing and debugging assistant tool for Death Road to Canada, built on the Qt framework. It enables real-time viewing and modification of game data such as characters, entities, and global resources by reading from and writing to the game process memory.

The tool provides an intuitive graphical interface with core functionalities including process attachment, character attribute editing, entity management, global resource manipulation, and weapon modification. It is suitable for game debugging, data research, mod development, and similar use cases.

---

## Key Features

### 1. Process Management
- Enumerate current system processes, with filtering by process name or PID.
- Attach to the target process with one click to gain memory access permissions.
- Display attached process information and module base address.

### 2. Character Panel
- List all in-game characters, selectable by name.
- **Basic Attributes**: character name, Perk, Trait, description, health, and extra speed.
- **Status Flags**: 2 status fields, one for female and one for pet.
- **Core Attribute Table** (13 items total):
  - Morale, Attitude, Composure, Charm, Intelligence, Loyalty, Medical, Mechanical, Shooting, Strength, Dexterity, Fitness, Vitality.
  - Each attribute supports base value, bonus value, with automatic effective value calculation and a "known" flag.
- **Resources**: edit 8 resource types (Food, Gas, Medical, Bullets, Rifle, Shotgun) quantities.
- **Weapon Slots**: 3 weapon slots, each supports weapon ID selection, quantity setting, and lock state.

### 3. Entity Panel
- Display all game entities (humans, zombies, items, projectiles, furniture, etc.) with filtering by type and region.
- **Entity Flags**: no collision, invisible, no drawing, glow, unhittable, damage immunity.
- **Physical Properties**: 3D coordinates, 3D velocity, mass, friction, bounciness.
- **Health** and **AI State** (AI state value, AI idle time).
- **Entity Operations**:
  - Set target entity
  - Teleport current entity to target entity position
  - Swap positions and regions of two entities
  - Destroy entity (character destruction requires additional steps, e.g., setting the character's health to 0)
  - Spawn entity (only zombies are supported)

### 4. Global (Mission) Panel
- Display the 4 character IDs in the current mission (read-only).
- **Global Resources**: edit 8 resource type quantities.
- **Storage Weapons**: 15 storage slots (3 rows × 5 columns), each slot supports weapon ID and quantity settings.
- **Send Script Command**: send built-in game console commands.

---

## Technical Architecture

- **Development Framework**: Qt 6 (C++)
- **Threaded Memory Operations**: Uses the `MemoryManager` class to encapsulate Windows process memory read/write operations.
- **Data Parsing**: `GameDataReader` handles reading and writing structured data from/to memory, including characters, entities, and global data, based on fixed memory offsets and structure layouts.
- **UI Design**: Uses `.ui` files generated by Qt Designer, combined with custom delegates (`SpinBoxDelegate`) for in-table numeric editing.
- **Refresh Mechanism**: A timer (500ms) periodically refreshes data for the currently active tab; the interval can be adjusted.

## Build and Run

### Requirements
- Windows OS (relies on Windows API for process memory operations)
- Qt 6 or later (CMake)
- C++11 or newer compiler (MSVC / MinGW)

### Build Steps
1. Open the project in Qt Creator and use CMake to generate build files.
2. Ensure all source files are included.
3. Build the project to generate the executable.

### Running
- Click the "Refresh" button to enumerate the process list, and enter a process name to filter (typically `prog.exe`, and this is the default text).
- Select the target process and click "Attach" to establish the connection.
- After successful attachment, switch to the various tabs to view and modify data.

---

## Notes

- **Fixed Memory Offsets**: This tool is written for a specific game version's memory layout. If the game updates, the relevant offsets may need to be relocated.
- **Input Focus Protection**: When the user is editing an input field (e.g., QLineEdit, QSpinBox, etc.), the timed refresh is automatically paused to prevent accidental data overwrites.
